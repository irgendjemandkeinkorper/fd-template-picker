# Draft acceptance and handoff

## Journal the distinctions

Create a local per-site build journal containing the export SHA/catalog/module index digests, user-authorized target/actions, proposed and actual IDs, every created Page/Section, field owner and readback hash, current Library state, final ordered Section IDs, native saved/unpublished states, immediate-effect Theme/navigation settings, dependency mappings, evidence times and unresolved issues. Keep source identities in a separate source mapping. Record requested paths versus actual generated routes.

No successful click proves completion. Read the native saved values after reopen. An enabled Save button can mean unsaved changes; a disabled Save button plus matching readback provides stronger saved-state evidence. Explicit Page-row published/unpublished state is still separate. Existing Page rows can show the older title/count; inspect the loaded normal editable Page. Record historical/inactive base Sections separately from the actual ordered draft Sections. A first snapshot showing No Sections or default fields is not settled evidence: wait for the expected saved Title, slug and child list before judging or recreating.

## Check the intended draft

- Confirm one chosen style per required component, actual navigation labels, complete composite hero children and selected order. The purpose of the Private Parties component is private hire; a generic film-programme Events block is not equivalent.
- Check desktop and phone text containment, images, overlay backing/shadows, controls, prices, category labels and no horizontal scrolling. Wait for async widgets/media before sampling; a skeleton/loading caption is not complete evidence.
- Verify native compiled CSS scope matches each final-named Section and typography comes from the package rather than accidental source Theme inheritance. For Custom Sections, retain the visible HTML/code and iframe body checks plus saved CSS readback; CSS alone cannot establish that body content survived.
- Check Primary/Secondary and Dark/Background, derived CTA/tint pairs, protected caption foreground/backing, hover/focus, native errors/status and any configured seat states. The picker's two base-pair checks cannot certify arbitrary rendered pairs or photo overlays. Verify independent Header/Accent bindings where supplied by the current demo shell; preserve the declared alias limitations of older packages instead of silently changing them.
- Verify expected approved destination sample items/media and catalog filters; empty settings can intentionally bind local categories. Dynamic source IDs are not configuration defaults. A populated movie list is not proof of bookable sessions or checkout.
- For forms, inspect destination configuration and validation without sending real enquiries unless explicitly authorized. Check intended links without submitting purchases, memberships or real ticket transactions.
- Reopen Library imports to confirm Not Linked; check native history/record states and source independence as needed. Never Force Update to resolve a local draft style issue.

Admin's **Mobile Web** preview narrows a container while media queries and `vw` can still use the outer Chrome viewport. A narrow container with desktop columns is not proof of a failed true-phone breakpoint, and a plausible simulated phone is not a passed actual-phone check. For the agreed 390px phone check, set and verify an actual browser viewport after other browser authors finish; viewport overrides can affect the active foreground tab, so serialize them and reset afterward. Record whether the measurement came from Admin at an actual viewport, a simulated container or a consumer page. Admin previews also use the framework palette; even an actual 390px Admin check does not certify consumer Theme output or a physical device. If an unpublished page redirects to the homepage, record public draft QA as unavailable. Do not publish merely to complete a QA checklist. A later release can authorize a staging/publication path and real consumer checks.

For a standalone build, review its complete page plan and local routes, not only a long homepage. Use the current dedicated component source and exact saved Theme/Page/Section dependencies described in [standalone sites](standalone-sites.md). Require the intended native food layout and visibility; seven products do not imply seven visible photos in every design. Check the shared footer on Home and a supporting Page, the actual phone drawer and enquiry links to the local Visit Page. Record presentation acceptance separately from Library/mixed-design portability.

The current nine-demo rollout is in **US-BETA / INDY Demo**, with replacement Showcase **193**, and has subsequent explicit Page/widget publication authorization. Keep existing working URLs and display-only ticketing. That permission covers the specified rollout; it does not change this skill's draft-stop default, authorize another hosting/deploy test or prove every route/module passed QA. ## Stop for review

Report the exact Region / Circuit / Site, final site name, selected mix and export SHA. For reference authoring without an export, state that fact and give the actual source-package hashes instead. Give a short table of created objects, state and review evidence, clearly separating saved Page drafts from immediate-effect site settings and any authorized hosted shell. Include pending content/media/portability/consumer checks and narrow rollback through the created objects/history. Removing a Site/Circuit, unpublishing or deleting seeded data requires its own authorization; do not perform cleanup by assumption.

For the default draft build, stop when all work that can be done in draft is complete. No Page/Global Widget publish, register push, custom domain, real transaction or deploy follows automatically. If the user has separately released the exact work, retain that authorization and perform only its specified publication/QA actions; do not ask for the same permission again or treat a draft-only request file as a release grant. If module readiness blocked assembly, deliver the concrete packaging plan instead of “site complete.” If a provision operation had an unknown outcome, record it and resolve the scoped inventory before any retry.
